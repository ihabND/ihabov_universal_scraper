API reference

One endpoint, two kinds of output.

Fetch any public web page and get back its formatted HTML, or, on supported sites, the page's data as structured JSON. The scraper uses a real browser's network fingerprint, follows redirects safely, and blocks requests to internal addresses.

Base URL

https://ihabov-universal-scraper.fly.dev

Authentication

Every request needs an API key, sent in the X-API-Key header. Keys are handed out personally; there is no sign-up.

X-API-Key: YOUR_API_KEY

Don't put the key in the URL, since query strings end up in logs and browser history. A missing or wrong key returns 401.

GET/scrape

Fetches a page and returns its content.

Query parameters

NameTypeRequiredDescription
urlstringYes The page to scrape. Must start with http:// or https://. URL-encode it if it contains & or ? (most HTTP libraries do this for you).
modestringNo html (default): the full HTML, formatted, as one string in content.
json: the page's data as structured JSON in parsed. Only works on supported sites.
browserstringNo auto (default): fetch the page normally, and only if the site blocks it (a bot check, or status 202, 403, 429 or 503), try again with a real headless browser. With mode=json, also when a page that loaded fine doesn't contain the expected data (an error page like a 404 is not retried). What worked is remembered per site for a day, so the next request starts there.
never: don't use the browser.
always: go straight to the browser, for sites you know need it. Slower: a few seconds per page.

Response

A successful call returns 200 with this JSON body:

FieldTypeDescription
urlstringThe normalized URL that was scraped.
status_codeintegerThe HTTP status the target site returned.
okbooleantrue if the target site answered with a 2xx status and the page isn't a bot check.
fetched_withstringhttp for a normal fetch, browser when the headless browser was used.
contentstring or nullThe formatted HTML with mode=html, otherwise null.
parsedobject, array of objects or nullThe page's data with mode=json, otherwise null. See JSON mode.

ok and status_code describe the page, not the API call. A page that returns 404 still comes back as a 200 from the API, with "ok": false, so you can see the error page's content. The same goes for a page that stayed blocked by bot protection after every way of fetching it (with mode=json, that is a 502).

Example response (mode=html)

{
  "url": "https://example.com/",
  "status_code": 200,
  "ok": true,
  "fetched_with": "http",
  "content": "<!DOCTYPE html>\n<html lang=\"en\">\n <head>\n  <title>\n   Example Domain\n  </title>\n ...",
  "parsed": null
}

POST/scrape/batch

Scrapes up to 50 URLs in one call. Every URL is handled exactly as GET /scrape would handle it, with the same checks, cache and browser fallback. A URL that fails doesn't fail the batch: its error is reported next to it.

Request body (JSON)

FieldTypeRequiredDescription
urlsarray of stringsYes1 to 50 URLs. The same page listed twice is scraped once.
modestringNohtml (default) or json, applied to every URL.
browserstringNoauto (default), never or always, applied to every URL.

Response

200 with results in the same order as urls, plus succeeded and failed counts. Each result has the url as sent, a status (200, or the error status /scrape would have returned), and either result, shaped like a /scrape response, or a detail message.

{
  "results": [
    { "url": "https://www.knjizare-vulkan.rs/domaci-klasici/25486-tvrdava", "status": 200,
      "result": { "url": "...", "status_code": 200, "ok": true, "fetched_with": "http", "content": null, "parsed": { "name": "TVRĐAVA", ... } },
      "detail": null },
    { "url": "https://example.com/", "status": 400, "result": null,
      "detail": "JSON isn't available for this page. Supported sites: ..." }
  ],
  "succeeded": 1,
  "failed": 1
}

A batch counts as one request per URL against your quota, and is refused as a whole with 429 if it doesn't fit. To be gentle on the sites you scrape, at most 4 URLs of one site are fetched at the same time, started at least a quarter of a second apart. Batches that need the browser take longer: allow a few minutes for 50 such URLs.

Errors

Errors use standard HTTP status codes and a JSON body with a detail message:

{
  "detail": "Invalid URL, only HTTP and HTTPS."
}
StatusMeaning
400The URL is invalid, or uses a scheme other than http/https, or mode=json was sent for a page that isn't supported, or browser=always was sent to a server where the browser is turned off.
401The API key is missing or wrong.
403The URL, or a page it redirects to, points to a private or internal address (like localhost or 192.168.x.x), which is not allowed.
413The page is larger than 5 MB.
415The URL is not an HTML page (for example a PDF, image or JSON file).
422A parameter is missing or has an invalid value, like mode=pdf, or a batch has no URLs or more than 50. The detail field is a list saying which parameter is wrong.
429Rate limit or quota exceeded, see Rate limits. The body says which limit, like {"detail": "Rate limit exceeded: 10 per 1 minute"}, and the Retry-After header says how many seconds to wait.
502The page couldn't be fetched: the site is down, its name doesn't resolve, it timed out, or it redirected too many times. With mode=json, also when the page didn't contain the expected data (for example a 404 page, or the site changed its layout), or when the site's bot protection blocked every way of fetching it.
503Every headless browser was busy for 15 seconds. Wait a moment and try again.

Rate limits

Requests with a valid key are counted against that key's quota: 300 URLs per minute and 10,000 per day. Every URL counts, including ones served from the cache, so a batch of 20 URLs uses 20.

Requests with a missing or wrong key are limited to 10 per minute per client IP address, so keys can't be guessed quickly.

Over either limit the API answers 429 with a Retry-After header in seconds.

Examples

curl

curl -H "X-API-Key: YOUR_API_KEY" \
  "https://ihabov-universal-scraper.fly.dev/scrape?url=https://scrapeme.live/shop/Bulbasaur/&mode=json"

Python

import requests

response = requests.get(
    "https://ihabov-universal-scraper.fly.dev/scrape",
    params={"url": "https://scrapeme.live/shop/Bulbasaur/", "mode": "json"},
    headers={"X-API-Key": "YOUR_API_KEY"},
    timeout=120,
)
response.raise_for_status()

print(response.json())

Python, many pages at once

import requests

urls = [
    "https://www.knjizare-vulkan.rs/domaci-klasici/25486-tvrdava",
    "https://www.knjizare-vulkan.rs/domaci-klasici/312916-izabrana-dela-mese-selimovica-tp",
]
response = requests.post(
    "https://ihabov-universal-scraper.fly.dev/scrape/batch",
    json={"urls": urls, "mode": "json"},
    headers={"X-API-Key": "YOUR_API_KEY"},
    timeout=300,
)
response.raise_for_status()

for item in response.json()["results"]:
    if item["status"] == 200:
        print(item["result"]["parsed"]["name"])
    else:
        print(item["url"], "failed:", item["detail"])

JavaScript

const params = new URLSearchParams({ url: "https://example.com", mode: "html" });

const response = await fetch(
  `https://ihabov-universal-scraper.fly.dev/scrape?${params}`,
  { headers: { "X-API-Key": "YOUR_API_KEY" } },
);
if (!response.ok) throw new Error((await response.json()).detail);

const data = await response.json();
console.log(data.content);

Limits and behaviour

WhatLimit
Page size5 MB
Timeout per request to the target site10 seconds
Total time for the plain fetch25 seconds, covering all retries, waits between them and redirect hops. After that the page counts as unreachable (502, or the browser with browser=auto).
RetriesUp to 2, with increasing waits, on timeouts and on 429, 502, 503, 504 from the target site, as long as they fit in the 25 seconds. A bot-check page is never retried: the browser is tried instead.
RedirectsFollowed automatically, up to 5. Every hop is checked against the internal-address block.
CachingA fetched page is kept for 10 minutes (30 seconds if the site returned an error or a bot check) and shared by mode=html and mode=json, so asking for both fetches the page once. Separate per browser option, shared by all API keys. The same request sent while one is running waits for it instead of fetching again.
BatchesUp to 50 URLs, 8 fetched at a time per API key, at most 4 per site at once and started at least 0.25 seconds apart. Batch URLs wait up to 2 minutes for a free browser instead of 15 seconds.
Content typesHTML only (text/html, application/xhtml+xml)
BrowserUp to 2 at a time (a request waits up to 15 seconds for a free one, then gets 503), 30 seconds to load the page, up to 20 seconds for a bot check to finish, and up to 5 seconds for scripts to finish rendering. Images, fonts and video are not loaded. Every connection the scraper makes itself, the browser's included, goes through a local guard that only connects to public addresses, so redirects and scripts can't reach internal ones either.
Sites that blockWith browser=auto, a site that blocked a plain request is sent straight to the browser for the next day; after that, a plain request gets another try. Known parser sites that block, like IMDb, start out marked. If the site passes a bot check in the browser, the resulting cookies are kept for up to 4 hours for your key only (in Redis, so they survive server restarts), and later pages from that site are tried over plain HTTP with them first, which is much faster.
JSON mode in the browserStops as soon as the page contains the data, instead of waiting for everything else on the page to load.

First request after a quiet period: the server sleeps when idle, and waking it adds 2 to 5 seconds. Use a client timeout of at least 120 seconds: a slow site can use the whole 25-second fetch budget and then a full browser run on top.
